该能力每回合一次，支付 2 Active Energy 并弃 1 手牌：

- 弃牌属于 μ's：看牌堆顶 4 张，其中 2 张加入手牌，其余进入控室。
- 弃牌属于其他作品：从支付费用之后的控室回收 1 张 Live。
- 如果弃置的其他作品卡本身就是 Live，可以回收刚弃置的那张卡。
- 公开控室存在合法 Live 时必须选 1 张；没有时完成费用后不回收，不阻塞整局。
- 分支由已验证的实际弃牌决定，不由前端 / AI 自选；费用不满足时整步回滚。

## 原型问题与修正

旧原型在费用 ID 已清空后才判定分支，且将必选回收写成最少 0 张；inspection 完成后还可能
执行其他分支的回收操作。本次在费用执行前锁定分支，费用后只暴露对应目标，并隔离后续操作。
支持分步支付以及在 `activate_effect` 同时提交费用，两种入口复用同一验证与结算流程。

UI 的费用选牌不显示可选分支；后续显示中文 / 日文的只读费用判定结果。
同一个 invocation 进入下一阶段时清空旧选牌，不能把已弃置的卡当作回收目标提交。
AI v0 / v1 / v1.1 和 deterministic sandbox 按当前 legal choice type 处理，而不是误读最终
分支元数据，避免丢失弃牌费用选择。

## 可复核的行为断言

| 场景 | 期望与断言 |
|---|---|
| μ's 成本 | 两张 Energy Wait、弃牌进控室、按顶牌顺序检查 4 张、必须选 2 张 |
| μ's 后续 | 所选 2 张入手，其余入控室，不额外回收其他 Live |
| 其他作品成本 | 仅出现控室 Live 候选，必须选现存的 1 张 |
| 控室无 Live | 费用仍支付，选择范围变为 0，正常结束 |
| 成本是其他作品 Live | 候选包含刚弃置的 Live，可回收自身 |
| 伪选分支 | 拒绝与弃牌作品不符的分支，原始状态不变 |
| 非法成本 | 错误 / 重复手牌 ID、不足 Energy、过期 revision 不改变状态 |
| 少选 inspection | 0 张不能冒充“选 2 张”，待选状态保持 |
| 次数限制 | 完成后本回合不再提供该起动能力 |
| 查看数量不足 | 开始查看前刷新，原有牌顶顺序不变，控室洗切后补在牌堆下方 |
| AI | 三种 policy 分别走两分支，所有操作由 LegalAction 产生并通过引擎验证 |
| Replay | 序列化初始快照后重放相同行动，最终快照一致 |
| 真实登记 | 当前 registry 的该 entry 本身完成两条分支，不只测人工构造的 DSL |
| 双方视图 | inspection 仅己方可见；入手后继续隐藏，进入控室的余牌对手可见 |
| UI | 费用步骤无需分支按钮；后续选择已重置，完成必选目标前不能确认 |

原查看牌堆流程的暂存区域曾被直接当作公开信息传给对手；本轮为 Online payload、
AIObservation 和 API Play 输入统一增加待查看牌的隔离。没有改变权威 MatchState 或 Replay。
这不是全协议隐藏信息安全审计，其他公开 / 私有边界仍需后续矩阵验证。
